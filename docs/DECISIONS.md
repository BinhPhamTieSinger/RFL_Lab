# Decision log

| # | Date | Decision | Why |
|---|---|---|---|
| D1 | 2026-11-06 | Rebuild on a new structure instead of refactoring the authors' code in place. Their code stays untouched as the reference implementation. | The authors' code passes all settings through one 59-field config plus ~28 hidden in-code defaults, puts every method's local training in one 959-line class, and splits FedHEP into two engines that behave differently. Parity tests against it are what make the rebuild trustworthy. |
| D2 | 2026-11-06 | One `Detector` interface for both levels (clients in a parent, parents at Global). | Lets the drill-down defense be two detectors composed, and lets any client-level detector be reused at parent level. |
| D3 | 2026-11-06 | Quality gates: ruff, mypy, import-linter (layer rule), pytest + Hypothesis property tests, graphify code graph. | Each covers something the others don't: style and bug patterns, types, architecture, behaviour, structure overview. |
| D4 | 2026-11-06 | Graphify is used for the code graph only. | It maps structure (modules, links, clusters, most-connected nodes). It does not check correctness. Correctness comes from property tests that state invariants (e.g. "weight 0 removes a sender"), checked on hundreds of generated inputs. Full formal verification is not practical for PyTorch training code. |
| D5 | 2026-11-06 | Experiments run on your Mac (MPS); the cloud workspace only runs tests. | The cloud workspace has no GPU. |
| D6 | 2026-11-06 | Report accuracy the way the authors' code does: pooled over all clients' test images (sample-weighted). Also record the plain mean over clients and bottom-10%. | The paper's text says "mean over clients", but its numbers come from the pooled metric. Matching it is required for parity; recording both lets either be compared. |
| D7 | 2026-11-06 | Match the authors' deterministic pieces exactly (partitions, subsets, normalization, model and initial weights, learning-rate schedule, aggregation rule), but don't copy their random-number call order during training. | Copying incidental RNG consumption would tie the code to quirks of their implementation. Training parity is judged statistically across seeds instead. |
| D8 | 2026-11-06 | The server averages BatchNorm running statistics with the weights, as the authors do. (Updated in 1d: every server now works on the authors' flat state vector, so the integer batch counter is averaged too and truncated on load, as in their code.) | The counter is never read during training or evaluation, and averaging an integer is meaningless. |
| D9 | 2026-11-06 | FedHEP is ported as the authors' recorded runs execute it: all three heads train together for 5 epochs with binomial loss weights. Their two-stage schedule is not ported. | `high_cardinality_two_stage` is False in every recorded run, so that code path never executes. |
| D10 | 2026-11-06 | Keep the authors' quirks in the faithful port, documented where they occur: ensemble weights start from [0.333, 0.333, 0.334] (not the prior) and are stored as probabilities but reused as logits; grouping and parent decisions use the full flattened update including BatchNorm counters. | Phase 1 must reproduce their numbers. Each quirk becomes a candidate change in Phase 3, tested against this baseline. |
| D11 | 2026-11-06 | The FedHEP server works on flat state vectors (`rfl.core.state`) in state_dict order. | Grouping uses a random projection that maps coordinates by position; any other layout gives different groups. |
| D12 | 2026-11-06 | The random projection is generated in row chunks instead of one D × 256 matrix. | Theirs allocates 3.5 GB per regrouping. `RandomState` draws normals in a fixed stream, so the chunks are exactly their matrix (tested). |
| D13 | 2026-11-06 | Attacks live in `rfl/attacks` and are applied by the server around local training (targets for label flipping, uploads for the others); attackers are chosen with the authors' rule (each client independently with probability q), so the number of attackers varies by seed. | Parity with the authors' attack table requires the same attackers. A fixed-count rule can be added for Phase 2 as a separate, clearly named option. |
| D14 | 2026-11-06 | Attackers are left out of the accuracy metrics; honest clients isolated by the defense are still scored. | As in the authors' `evaluate_ensemble`. |
| D15 | 2026-11-06 | Phase 2 benchmarks use an exact attacker count (3 of 15) instead of the authors' probability rule. | With the probability rule the number of attackers varies by seed (1 to 6 at 20–30%), which dominated the spread in Phase 1c. A fixed count makes methods and seeds comparable. The authors' rule stays available for parity runs. |
| D16 | 2026-11-06 | Detection is scored from what each method itself reveals: Multi-Krum flags the clients it leaves out (trust = −Krum score); Defended FedHEP flags isolated and hard-rejected clients (trust = Global share); methods without a detector flag nothing. | One metric definition for every method, without adding detectors to methods that have none. |
| D17 | 2026-11-06 | Backdoor success is measured with each method's own prediction rule. | For FedHEP that includes masking classes a client never trained on, which blocks a backdoor whose target class the client lacks. That is part of the method, so it counts; the per-client view will show how much of FedHEP's robustness comes from it. |
| D18 | 2026-11-07 | Screening uses a robust z-score whose scale is max(1.4826 MAD, 0.1 × |median|), and does not screen fewer than 5 senders. | Without the floor, a tight consensus makes MAD tiny and an honest client 0.04 below the others gets z = −5 (seen on synthetic data). The floor scales with the scores, so shrinking cosines still leave z unchanged. |
| D19 | 2026-11-07 | Phase 3 screens variants on one seed first (seed 42), then confirms the best on all three. | 20 runs instead of 60 for the first pass; seed 42's Phase 2 rows (same attackers) are the matched baseline. A one-seed difference smaller than the Phase 2 seed spread is treated as no difference until confirmed. |
| D20 | 2026-11-07 | Readmission scores isolated clients against the reference and spread of the clients currently kept, and readmits at evidence > −cut/2 (hysteresis). | Scoring them against a reference that includes them would let attackers pull it; the gap between the isolate and readmit levels stops a client flickering in and out. |
| D21 | 2026-11-07 | The exclusion cap is a third of all clients. | The usual Byzantine assumption is fewer than half the clients malicious; a third leaves room for 3 attackers plus 2 borderline honest clients out of 15 while making a total collapse impossible. |
| D22 | 2026-11-08 | Isolation stays permanent; readmission and the cap are kept as options but not used going forward. | Three seeds: readmission brought attackers back late in training (when update directions carry little information) and the cap let backdoor attackers back in; both lowered accuracy under attack and raised backdoor success. |
| D23 | 2026-11-08 | A variant counts as an improvement only when its paired per-seed difference has the same sign on all three seeds and its mean exceeds the Phase 2 seed spread (about 1–1.5 points). | Three seeds can't support formal significance tests; consistent sign plus size is the honest bar. |
| D24 | 2026-11-09 | Phase 3 result is FedHEP+ with the kept-population yardstick (3b), not the full-population one (3c). | 3c had more false isolations and lost the backdoor protection (54–74% success vs 21%), with no gain elsewhere. |
| D25 | 2026-11-09 | Parents are judged against random groups of the same size (permutation test), not on the clients' yardstick. | A group mean is always more aligned than a single client, so on the client yardstick every parent looks good. Comparing with same-size random groups removes that size effect for any number of parents. |
| D26 | 2026-11-09 | The drill-down (v1) is not adopted; FedHEP+ (Phase 3) stays the best method. The code stays as an off-by-default option. | Phase 4, three seeds: no setting met D23; the concentrated backdoor (its target case) got worse (21.5% → 39.7% success) because one-round exclusion made attackers look more normal and delayed their isolation; honest parents were falsely flagged in up to 11 of 30 rounds with no attack. |
| D27 | 2026-11-09 | Drill-down v2 turns a flagged parent into evidence against the members that share its unusual direction (leave-one-out alignment vs clients outside the parent), never a one-round exclusion; parents need ≥ 3 members. Comparing each parent with its own history was considered and dropped. | Addresses the three v1 failures found in the logs (exclusion hid the attackers' contrast; the stricter cut couldn't tell members apart; false flags from tiny or odd honest parents). Attackers are present from round 1, so a parent's own history would absorb the attack. |
| D28 | 2026-11-09 | Drill-down v2 is not adopted, and Phase 4 is closed. FedHEP+ (Phase 3) stays the best method; we move to Phase 5 (wider search). | Phase 4b, three seeds: concentrated-backdoor success 21.5% → 1.9%, but it failed the accuracy criterion (−1.1 to −1.7) and the no-attack false-isolation criterion (19 vs 10). Honest members of a FedHEP parent align with each other (alignment z median 1.0, up to 2.8 in flagged parents) in the same range as attackers (3.0–3.6), so no cutoff separates them; a third design would face the same overlap. |
| D29 | 2026-11-09 | Phase 5 compares established rules inside FedHEP's Global step (Option A), not as standalone FedAvg defenses. Rules see weight updates only (BatchNorm buffers by coordinate median, as SCCF); parents run SCCF over the clients the rule accepts. Trimmed mean and Bulyan assume 3 attackers (the oracle the authors gave Multi-Krum). FLTrust's 100 root images are training images no client holds, repeated to the median client's size so the server takes as many SGD steps as a client. FLAME is run both on local models (the paper's equations) and on updates (the other reading). | Same model, personalisation and attacks as FedHEP+, so differences come from the rule. Weights only, because Phase 2 showed BatchNorm counters dominate distances. Root images from outside the clients' data keep the clients' data identical to every other method's. |
| D30 | 2026-11-12 | FedHEP+ stays the main method after Phase 5. The follow-up session's code (MAD logging, absolute floor, patience, ALIE / Min-Max, skew audit) is adopted as is, with ALIE's z set to the paper's formula (0.43 for n = 15, m = 3; 0.39 for n = 20, m = 4). Its 108-run generalization sweep is replaced by two smaller sweeps (attacks, q). | Three-seed Phase 5: no rule beats FedHEP+ overall. The follow-up code passed every check here; its z = 1.0 was stronger than the attack it names; about 30 of its generalization runs repeated existing ones. |
| D31 | 2026-11-14 | Phase 6 tests layer L0 (influence bound) first and alone, as a Global-step rule `arc_nnm_tm`: ARC, then NNM, then coordinate trimmed mean, f = assumed attackers (3 for 15 clients, 4 for 20); worker momentum kept by the server, β ∈ {0, 0.5}. | L0 addresses both measured failures without screening: it bounds what undetected ALIE / Min-Max attackers can do, and it isolates nobody, so it cannot make false isolations. ARC's paper defines k = ⌊2(f/n)(n − f)⌋ and the clip norm but not ARC's order relative to NNM; clipping first keeps one large row out of its neighbours' averages. The NNM and ARC papers use β = 0.9 per optimization step; here one momentum step is one round of a 30-round run, where β = 0.9 would keep a round's update at more than half weight for 6 rounds, so 0.5 (half-life one round) is tested against no momentum. |
| D32 | 2026-11-14 | Backdoor recovery after isolation becomes hypothesis H8 of the research plan. | 20 clients, α = 0.5, FedHEP+ isolated all 5 backdoor attackers by rounds 11–15 in every seed, yet success (measured on honest clients only) kept rising afterwards, by 17–47 points by round 30 in all five runs where every attacker was isolated. Isolation alone does not remove an implanted backdoor. Note for H3 (reversible trust): D22 found that readmission brought attackers back late in training, so reversibility must be tested against that failure, not assumed safe. |
